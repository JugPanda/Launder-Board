# Decision Scorecard

Use evidence rather than enthusiasm alone. Score each finalist from **1 (weak)** to **5 (strong)** and add one sentence explaining every score.

## Criteria

- **Problem clarity:** Can a judge understand the problem in one sentence?
- **Demo impact:** Is there an obvious before-and-after moment on stage?
- **Hackathon feasibility:** Can the core experience be built and rehearsed within the event?
- **Data readiness:** Can we legally and reliably obtain enough useful demo data?
- **Technical distinction:** Does the implementation demonstrate more than a thin prompt wrapper?
- **Result explainability:** Can the product show why a result matched?
- **Reliability:** Can the main demo survive network, model, and API failures?
- **User value:** Would a real person choose to use this after the event?
- **Team fit:** Does the concept match the team's strongest skills?
- **Expansion potential:** Is there a credible next step after the MVP?

## Veto questions

Reject or rescope a concept if any answer is “no”:

- Can we demonstrate it without exposing private or copyrighted material improperly?
- Can we prepare a deterministic fallback if an external service fails?
- Can we explain what the technology contributes beyond a normal keyword search?
- Can we finish the core flow early enough to rehearse it?
